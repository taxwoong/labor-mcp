# 임금대장 정규화 입력 스키마 + 엑셀 변환 가이드

> MCP 리소스 URI: `labor://schema/임금대장-입력`
> 기준일: 2026-08-28 (개발계획.md 리서치 확정. 시행령 제27조는 2025-10-23 시행본 확인)
> 용도: `analyze_payroll` 입력 스키마 확정본. Claude는 어떤 형태의 임금대장(엑셀·표)이든
> 이 스키마의 JSON으로 변환해 도구를 호출한다. **계산·판정은 전부 서버가 수행** —
> Claude의 역할은 정확한 변환과 결과 해석이다.

## 1. 스키마 확정본

```json
{
  "사업장": {"상시근로자수": int, "연도": int, "탄력선택근로제": "없음|탄력|선택"},
  "직원": [
    {
      "사원ID": str, "성명": str(선택), "입사일": "YYYY-MM-DD", "퇴사일": "YYYY-MM-DD 또는 null",
      "주소정근로시간": float, "수습여부": bool, "계약기간1년이상": bool, "단순노무직": bool, "감시단속승인": bool,
      "월별": [
        {
          "연월": "YYYY-MM",
          "임금항목": [{"명칭": str, "금액": int, "지급주기": "매월|격월|분기|반기|연간|일회성",
                        "성격": "기본급|정기상여|식대|교통비|직책수당|가족수당|기술수당|성과급|연장수당|야간수당|휴일수당|연차수당|기타",
                        "실비변상": bool(기본 false), "최소보장액": int(성과급일 때만, 선택)}],
          "근로일수": int 또는 null, "총근로시간": float 또는 null,
          "연장시간": float 또는 null, "야간시간": float 또는 null, "휴일시간": float 또는 null,
          "주별근로시간": [float] 또는 null,
          "공제내역": [{"항목": str, "금액": int}] 또는 null
        }
      ]
    }
  ]
}
```

### null의 의미 (중요)

- **null = "임금대장에 그 정보가 없음"** — 시행령 제27조 기재사항 누락 검사와 연동된다.
  실제 값이 0인 것(예: 그 달 연장근로 0시간으로 **기재**됨)은 `0`으로, 칸 자체가 없거나
  공란이면 `null`로 넣는다. 0과 null을 섞으면 누락 검사가 통째로 틀어진다.
- 단, **4인 이하 사업장·감시단속 승인자(근기법 제63조)는 근로시간류(7·8호) 기재 생략이
  적법** (시행령 제27조③) — 서버가 `상시근로자수`·`감시단속승인` 필드로 자동 예외
  처리하므로, 없는 값을 억지로 추정해 채우지 말고 null 그대로 둘 것.

| 사업장.연도 | 최저임금·산입비율 등 연도 파라미터 선택 (`labor_constants`) |
| 사업장.탄력선택근로제 | 주52시간 검사 기준 전환 (근기법 제53조② — 탄력·선택근로제는 정산 방식이 다름) |
| 입사일·퇴사일 | 고용 연월일(시행령 제27조 3호), 연차·수습기간·퇴직 판정 |
| 주소정근로시간 | 월 환산 기준시간·주휴 비례 계산 (주 40h → 209h) |

| 주별근로시간 | 주52시간 검사 (제50조 + 제53조① 연장 12h). 주 단위 기록이 있을 때만 |
| 연장·야간·휴일시간 | 가산수당 이론치 대조 (제56조 — 5인 미만은 가산 미적용 자동 분기) |

## 2. 시행령 제27조(임금대장 기재사항 10개 호) ↔ 스키마 대응표

| 호 | 기재사항 | 스키마 필드 | 비고 |
|---|---|---|---|
| 1 | 성명 | `성명` (선택) | |
| 2 | 특정 정보 (생년월일·사원번호 등) | `사원ID` | 생년월일은 개인정보 최소화를 위해 스키마에 미수집 — 기재 여부는 Claude가 원본 대장에서 직접 확인해 보고 |
| 3 | 고용 연월일 | `입사일` | |
| 4 | 종사 업무 | (스키마 미수집) | Claude가 원본에서 기재 여부 확인. `단순노무직` 필드는 수습 감액 판정용이지 이 호의 대체가 아님 |
| 5 | 임금·가족수당의 계산 기초 사항 | `주소정근로시간` + `임금항목` 구조 (부분) | |
| 6 | **근로일수** | `근로일수` | |
| 7 | **근로시간수** | `총근로시간` (+`주별근로시간`) | |
| 8 | **연장·야간·휴일근로 시간수** | `연장시간`·`야간시간`·`휴일시간` | |
| 9 | 기본급·수당 등 내역별 금액 | `임금항목[]` | |
| 10 | 공제 내역 | `공제내역[]` | |

**기재 예외** (누락 플래그에서 제외해야 함):
- 시행령 제27조②: **30일 미만 일용직**은 2·5호 생략 가능.
- 시행령 제27조③: **4인 이하 사업장·제63조 근로자(감시단속 승인 등)**는 7·8호 생략 가능.

6~8호 덕분에 임금대장만으로 주52시간·가산수당 검증까지 가능하다는 것이 `analyze_payroll`
설계의 근거다. 참고: 임금명세서 기재사항은 시행령 제27조의2 6개 호(특정 정보/임금지급일/
총액/구성항목별 금액/계산방법(연장·야간·휴일 시간수 포함)/공제내역) — 근기법 제48조②,
위반 시 과태료 500만원 이하(제116조②).

## 3. 엑셀 → 스키마 변환 가이드 (Claude용)

### 3-1. 흔한 임금대장 형태와 매핑

1. **월별 시트형** (시트 1장 = 1개월, 행 = 직원, 열 = 임금항목): 시트를 순회하며
   직원별로 `월별[]`에 누적. 시트명에서 `연월` 추출.
2. **직원별 시트형** (시트 1장 = 직원 1명, 행 = 월): 직원 단위로 바로 변환. 가장 수월.
3. **연간 집계형** (행 = 직원×항목, 열 = 1~12월): 열을 `연월`로 전개(unpivot)해 변환.

공통 규칙:
- 원본 열 이름을 `명칭`에 **그대로 보존**한다 (판정 결과를 원본과 대조할 추적성 확보).
- 합계·총지급액 열은 임금항목으로 넣지 않는다 (이중 계상). 서버가 합산을 수행.
- 금액은 정수(원). 천 단위 구분기호·통화기호 제거.

### 3-2. 항목 `성격` 분류 요령 — `labor://table/임금항목-산입매트릭스` 참조

- 명칭이 아니라 **실질**로 분류: "식대"라도 영수증 실비 정산이면 `실비변상: true`,
  전원 정액 지급이면 `식대`(실비변상 false).
- 상여 계열("상여금", "명절상여", "정기상여") → `정기상여` + 실제 `지급주기`가 판정의 핵심
  (격월·분기·연간 상여는 최저임금 불산입 — 최다 함정).
- 실적 연동 금품("인센티브", "성과금", "PS/PI") → `성과급`. 계약·규칙상 최소보장 조항이
  있으면 `최소보장액` 기재 (통상임금 판정 불확실 항목으로 분리 출력됨).
- **분류 불명 항목은 `기타`로 넣는다** (서버가 3축 모두 '불확실'로 처리). 스키마에 비고
  필드가 없으므로, 변환 완료 보고에 `기타` 처리 항목 목록과 원본 명칭·추정 성격을 첨부해
  사용자 확인을 받은 뒤 재분류한다. 임의로 그럴듯한 성격을 추정해 넣지 말 것.

### 3-3. 지급주기 추정 요령

- 매월 등장하는 항목 → `매월`.
- 특정 월에만 등장: 짝수(홀수) 달 반복 → `격월`, 3·6·9·12월형 → `분기`, 연 2회 → `반기`,
  연 1회 → `연간`, 1회성(경조금 등) → `일회성`.
- 12개월 전체 데이터가 없어 주기를 확정할 수 없으면 사용자에게 확인 — 지급주기가
  최저임금 산입 판정을 좌우하므로 추측 금지.

### 3-4. 근로시간·일수 변환

- 공란·열 자체가 없음 → `null` (0으로 채우지 말 것 — 위 null 의미 참조).
- `주별근로시간`은 주 단위 기록(주별 집계표·근태 기록)이 있을 때만. 월 총계만 있으면
  `null` — 이 경우 주52시간 검사는 해당 월에 대해 수행되지 않음을 결과 해석 시 고지.
- `총근로시간`은 실근로시간 (소정+연장 포함). 유급 처리 시간(주휴 등)과 혼재된 대장이면
  사용자에게 기준 확인.

### 3-5. 직원 속성 변환

- `수습여부`·`계약기간1년이상`·`단순노무직`은 임금대장에 없는 경우가 많다 — 근로계약서
  등 별도 자료로 확인하고, 확인 불가 시 보수적 기본값(수습여부 false)을 쓰되 변환 보고에
  "미확인" 목록을 명시한다 (수습 감액의 적법성 입증 책임은 감액을 주장하는 쪽에 있음).
- `감시단속승인`은 고용노동부장관 **승인서 존재**를 확인한 경우에만 true (근기법 제63조 —
  승인 없는 감시단속 업무는 일반 근로자와 동일 취급).
- `공제내역`은 4대보험·소득세 등 명칭 그대로. 법정 공제 외 항목(변상금 등)은 근기법
  제43조 전액지급 원칙 위반 소지가 있으므로 그대로 보존해 서버 판정에 맡긴다.

### 3-6. 변환 후 자기 검증 체크

- [ ] 직원 수·월 수가 원본과 일치하는가
- [ ] 임금항목 합계가 원본의 월 지급총액과 직원·월 단위로 일치하는가 (불일치 시 누락 열 탐색)
- [ ] 0과 null을 의미대로 구분했는가
- [ ] `기타`·"미확인" 항목 목록을 사용자에게 보고했는가

> **한계 고지**: 분석 결과는 입력 데이터(항목 분류·근로시간 기록)의 정확성에 종속된다.
> 변환 단계의 분류 오류는 판정 전체를 오염시키므로, 불확실한 분류는 반드시 사용자 확인을 거칠 것.
